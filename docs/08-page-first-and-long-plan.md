# 08. 페이지 우선 판독 · 긴 이미지 후보 실행 계획(실행 전 고정, 2026-10-26)

지시서는 `page-first-long-image-handoff-2026-10-25.md`이다. 범위는 아래 A·B 두 가지로 한정한다. 일반 페이지의 영역 bbox·ID, 배정·미배정 보존, 입력 처리, 결과 화면의 기본 틀은 유지한다.

## A. 페이지 우선 판독(`--read-mode page-first`)

### 실행 구조

1. **Stage 1 재사용**: 일반 페이지는 기존 Stage 1(`work/runs/stage1-merge-large`, 최종 실행의 Stage 1과 19페이지 동일)을 그대로 쓴다. OCR 영역 ID·bbox와 미배정 데이터를 다시 만들지 않는다.
2. **page/2 요청**: 페이지 1회에 이미지 2장을 보낸다.
   - 원본 페이지: 글자를 읽는 이미지.
   - 표시 사본: 영역 상자와 L 라벨만 그린 이미지. 위치 확인용이며, 이미지 2장 비용은 호출 기록 `images`에 남긴다.
   - 영역 목록: region_id·bbox(px)·표 후보 여부·OCR 후보를 준다. OCR 후보는 영역별 글자 조각을 문자열 순으로 정렬한 것이며 순서 정보가 없다. 경계 OCR은 영역 안 비율 0.5 이상만 넣는다.
   - 응답: 모든 region_id의 text와, 표 후보의 `is_table`·`rows`를 한 번에 받는다.
3. **영역 crop 확인**: 아래 일반 조건 중 하나라도 해당하는 영역만 확인 요청을 보낸다.
   - 일반 영역: `region-verify/1`(영역 원본 crop + 1차 페이지 판독 문구 + OCR 후보, 최대 8개 묶음).
   - 표 후보: `table-check/3` crop.
   - 경계 걸침·겹침 같은 맥락 근거만으로는 보내지 않는다.

   | 조건 | 내용 |
   |---|---|
   | `page_output_failed` | 페이지 응답이 계약에 실패했거나 text가 null |
   | `vlm_uncertain` | 페이지 판독이 uncertain=true |
   | `small_text_after_resize` | 서버 리사이즈 추정 배율 × 영역 OCR 글자 높이 중앙값 < **12px** |
   | `ocr_text_missing_in_page_read` | 영역 안(배정) OCR 줄이 1차 판독에 덮이는 비율 < 0.85 |
   | `ocr_digits_missing_in_page_read` | 영역 안 OCR의 숫자가 1차 판독에 없음 |
   | `table_rows_missing` / `table_rows_incomplete` | 표 판정이 true인데 rows가 비었거나, rows가 text를 덮는 비율 < 0.85 |

4. **병합**: 계약을 통과한 가장 나중 결과를 쓴다. 확인 요청이 실패하면 페이지 판독을 유지한다.
   - 1차 페이지 문구(`page_text`), 확인 사유, 호출 순서를 trace에 남긴다.
   - 결과 영역에는 `read_path`(page / page+verify / page+table / crop)를 둔다.
5. **문구 출처**: 최종 문구는 VLM 응답 그대로다. OCR 문자열을 정렬·접합하거나 OCR로 덮어쓰지 않는다. 파일·영역 ID별 분기는 없다.

### 작은 비교(고정 집합)

**고정 집합 6페이지**:

- 핵심 사례: f02_p01(설명·도해·비교 구조, L004), f12_p02(L022 여러 줄 항목명, L017·L021 항목-값).
- 대조군: f13_p01(항목-값, 원본이 커서 0.42배로 축소), f05_p01(5열 요약), f07_p02(L000 요약, L001 원문 표기), h01_p03(HWP 문서).

**비교 조건**:

- 기준선: 저장된 crop 실행 5회(full-c1·c2·c4·c2-mixed, final-2026-10-25)를 이 6페이지로 제한해 쓴다. 새 호출은 없다.
- 새 조건:
  - page-first(OCR 후보 포함) 2회.
  - page-first-noocr(OCR 후보 없음) 1회.
- 모두 동시성 2, 같은 서버·모델·temperature 0, 같은 Stage 1이다.

**호출 예상**: 실행당 페이지 6회 + 확인 약 4~10회 → 3실행에 약 30~50회.

**평가**: `eval_structure.py --pages`로 같은 6페이지만 센다. 정답은 `fixtures/gold`, 구조 정답은 `structure-gold.json`, 사례는 `vlm-cases.json`이다.

- f12_p02 L022 단위(항목명 2줄 → 값 2줄)는 이 실행 전에 구조 정답에 추가했다.
- 단어 집합·CER·줄 수만으로 통과시키지 않는다. 항목명 완결성과 값의 연결은 연결 단위로 판정한다.

**채택 기준**: page-first 2회 모두 아래를 만족해야 한다.

1. 계약: 6페이지의 모든 region_id에 결과가 1개씩 있고 bbox·ID가 바뀌지 않는다. 계약 검사를 통과한다.
2. f12_p02 L022 연결 단위가 보존된다(항목명 '중도해지 및 만기후 금리' 완결, 그 뒤 값 2줄).
3. f02 L004의 설명 문단 단위가 보존되고, L004 기대 줄 누락이 0이다.
4. 문구 보존(6페이지): 소속 영역 정확+근사 ≥ 기준선 최솟값 − 3, 기대 줄 누락 ≤ 기준선 최댓값 + 3.
5. 연결 단위 보존(6페이지) ≥ 기준선 최댓값.
6. 추가 구간(4자 이상) ≤ 기준선 최댓값 + 1. 기준선 5회에서 모두 오류가 없던 영역 중 새 오류 ≤ 2.
7. 6페이지 안의 정상 대조 사례(f02 L020, f13 L002, f12_p02 L017·L021의 '가입대상')가 모두 통과한다.

**판정**:

- 통과하면 B와 합친 전체 실행을 page-first로 한다.
- 미달이면 원인 사례를 보고, 고칠 수 있는 지시 문제는 1회만 수정해 다시 확인한다. 그래도 미달이면 결과와 함께 보고한다.
- OCR 후보 유무: noocr 1회가 4·5·6 기준에서 page-first보다 모두 같거나 낫고, OCR 오답 추종이 줄 때만 noocr를 고려한다. 그렇지 않으면 OCR 후보를 포함한다.

## B. 긴 이미지 후보 실행(`--run-candidate-boundaries`)

### 후보 경계(기존 탐색·판정 재사용)

후보 위치는 기존 탐색의 기하 후보(빈 띠 중앙)를 쓴다. 의미 판정은 두 근거로 한다.

- **VLM 관계 판정(M2)**: 기존 응답을 재사용하고, 없는 위치는 새로 1회씩 호출한다.
- **AI 시각 검토**: Claude가 원본을 보고 판단한다. **사람 검토가 아니다.**

두 근거가 모두 '독립 섹션'인 위치만 후보로 쓴다. 과거 오판 범주(버튼–설명, 탭–내용, 목록 항목, 표–각주, 제목–설명, 배지–설명)는 후보에서 뺀다.

**타일 구성 정책 `section-pack/1`**(실험값):

- 연속 섹션을 폭×2.5 안에서 묶는다. 이 값은 상한이 아니라 묶음 목표다.
- 안쪽에 후보 위치가 없는 섹션이 이 값보다 길면 통째로 한 타일로 둔다. 임의로 자르지 않는다.
- 동적 계획법으로 타일 수를 최소화하고, 같으면 가장 짧은 타일이 가장 긴 쪽을 고른다.
- 타일은 원본을 빈틈·중복 없이 덮는다.

**페이지별 후보**:

|---|---|---|
| f09 | 2131 | 각주 주6 끝 → '상품설명서 및 약관'. 빈 띠 111px, 라벨 safe, M2 독립. [0,2131]은 탭·우대금리 상자·표·각주가 이어진 한 섹션이다. 내부의 1243(표–각주), 184(탭–내용), 381(설명–표)은 과거 오판 범주라 자르지 않는다. 그래서 폭×2.5(1640)보다 길어도 통째로 둔다 |
| f11 | 1147 | 유의사항 목록 끝 → '상품설명서 및 약관'. 빈 띠 109px, 라벨 safe, M2 독립 |
| f08 | 937·1968·4117·4646·4821·5069(라벨 safe + M2 독립), 2656·3326 | 2656·3326은 이번에 M2 판정과 시각 검토를 한다 |

### 실행과 평가

1. **후보 계획 문서**: `fixtures/boundary-plans/*.candidate.json`(status candidate, `semantic_check.method` = `vlm_relation+ai_visual_review`)을 작성한다. 근거는 다음과 같다.
   - 경계 주변 원본 이미지
   - 교차하는 OCR·레이아웃 상자 수
   - M2 응답
   - 시각 검토 메모
2. **후보 실행 경로**: `--run-candidate-boundaries`로 명시했을 때만 후보 경계로 타일 OCR을 실행한다.
   - 페이지 실행 상태는 `CANDIDATE_RUN`이다. `READY`와 validated로 바꾸지 않는다.
   - 결과·화면에 '후보 경계·미검증'을 표시한다.
   - 기본 실행에서는 지금처럼 보류한다.
3. **좌표**: 타일 OCR의 원시 레이아웃 bbox는 원본 좌표로 이동만 한다. 영역 ID는 `<page>-t<k>-L<n>`이다.
4. **OCR 평가**(정답 대조): 기존 탐색 S25 및 W4·WHOLE과 비교한다. 레이아웃 누락(정답 줄이 상자 안에 있는지)과 글자 누락·오독(같은 위치 OCR 정오)을 따로 센다.
5. **판독**: 각 타일을 페이지처럼 page/2로 판독하고, 일반 조건에 해당하는 영역만 crop 확인한다(A와 같은 코드).
6. **결과 표시**: `CANDIDATE_RUN` 결과를 품질 통과나 확정 결과로 표시하지 않는다. `human_review`는 기록하지 않는다.
