test-tmp-file 5개 입력의 전체 파이프라인 결과(`work/pipeline/test-tmp-2026-10-27`)를 사용자가 원본과 대조해 찾은 오류 3건의 원인 분석이다.
코드는 아직 바꾸지 않았다. 진단 요청은 모두 새 폴더에 저장했고 최종 결과에 쓰지 않았다. 서버 설정은 바꾸지 않았다.

## 2. 표 영역 누락(tt03)

현재 규칙: 영역은 OCR 서버 응답의 `layout_det_res.boxes` 만으로 만든다(`regions.py::parse_view`). 어느 상자에도 50% 이상 들어가지 않은 OCR
글자는 `unassigned_texts` 로 보관만 하며 VLM 판독·상품 분류·라벨에 넘기지 않는다(docs/00 계약). Stage 1 검사는 `TEXT_OUTSIDE_LAYOUT` 경고만 낸다.

근거:

- 레이아웃 상자 29개 중 표 상자 0. 미배정 OCR 9개가 정확히 두 표와 왼쪽 항목명이다: 기본금리 / 기간·12개월·적용이자율·2.60%(적금) /
  기간·12개월·적용이자율·2.15%(예금). 그래서 최종 결과에 예금 기본금리 값 2.15% 가 없다.
- 문턱값 진단(`scripts/probe_layout_threshold.py`, 읽기 전용, `work/server-probe/tt03-table-threshold-2026-10-28`):

| layoutThreshold | 상자 수 | 오른쪽 표 | 왼쪽 표 |
|---:|---:|---|---|
| 서버 기본 | 29 | 없음 | 없음 |
| 0.3 | 28 | `table` 0.338·0.326(겹친 상자 2개) | `text` 상자 0.305·0.405 에 걸침, 표 아님 |
| 0.2 | 24 | 같음 | `text` 0.233 |
| 0.1 | 6 | 페이지 대부분이 `image` 0.106 상자 하나로 합쳐짐 | 같음 |

  오른쪽 표는 기본 문턱 아래 점수라 버려졌고, 왼쪽 표는 표로 잡히지 않는다. 숫자 하나로 문턱을 낮추면 다른 상자가 무너지고, 클래스별 문턱은
  서버 dict 키 버그로 막혀 있다(docs/06). 문턱값으로는 고칠 수 없다.
- 같은 원인으로 빠진 내용(오프라인 계산, 이웃 영역 최종 문구에 이미 있는 부분 겹침 OCR·한 글자 기호 제외): tt04 이벤트 제목('농협은행이 777명에게
  쓴다!', 'E/V/E/N/T', '경품안내'), n01 상품전환 안내 12줄(2묶음), h01 상단 표(비예금상품여부·홍보국협의여부·심의필번호), f09 예금보험 배지.
  웹 캡처 f02–f07 은 메뉴·푸터 62묶음. 모바일 캡처의 '검증서버(…)'·'캡처' 같은 화면 장식도 있다. 전체 22파일에서 86묶음.

수정 후보:

- **빈자리 영역(제안)**: Stage 1 결과의 미배정 OCR 을 줄 단위 인접(같은 줄: 세로 겹침 ≥ 줄 높이 50%·가로 간격 ≤ 6×줄 높이, 위아래: 세로 간격 ≤
  줄 높이·가로 겹침)으로 묶어 보충 영역을 만들고 같은 판독 경로로 읽는다. 출처 표시(`ocr_gap`)와 검토 코드(`layout_missed`)를 붙이고, 2행×2열 이상
  격자는 표 후보로 둔다. 오프라인 계산에서 tt03 의 두 표가 각각 한 묶음(적금 [463,1516,711,1576], 예금 [1150,1516,1427,1577])이 된다. OCR 재호출은
  필요 없고(기존 Stage 1 응답 사용) 빈자리 영역이 생긴 페이지만 다시 판독한다. docs/00 계약("영역 출처는 레이아웃 상자 하나")을 바꾸는 일이라
  사용자 확인이 필요하다.
- 표 상자만 낮은 문턱으로 한 번 더 받기: 위 진단상 왼쪽 표를 못 찾으므로 채택하지 않는다.

## 3. 상품 수 오류(tt02·tt03·tt05)

현재 흐름(inventory-first, 기본값): 상품 목록 호출 1회(묶음 전체 문구·표·이미지) → 상품이 하나만 연결된 페이지는 모델 호출 없이 그 페이지
영역 전부를 그 상품에 배정(`basis=single_product`) → 두 개 이상인 페이지만 배정 호출.

근거(실행 기록 `work/pipeline/test-tmp-2026-10-27/tt0*/semantic/trace`):

- tt02·tt03 응답은 `pages` 에 `["t1","t2"]` 를 냈지만 `targets` 에는 t1 만 있었다. 검사가 "targets 에 없는 대상 ['t2'] 를 페이지 연결이
  가리킴(무시)"을 기록만 하고 진행했고(`product_inventory.py::validate_inventory`), 페이지 후보가 하나가 되어 두 번째 상품 영역까지 첫 상품에
  자동 배정됐다. 상품의 `review.required` 는 false 였다.
- 빠진 두 번째 상품은 `mentions` 에서 `comparison`(정의: "같은 상품의 유형 비교, **다른 상품과의 비교**") 또는 `condition` 으로 분류됐다.
  나란히 놓인 두 상품을 '비교'로 읽는다.
- tt05 는 '상환방법' 아래 R25 '종합통장(마이너스통장)'을 `unsupported` 대상으로 추가했다. 템플릿 기준 `loan_named.name` 에 '마이너스통장,
  종합통장대출'이 상품명 패턴으로 있다. 기준 실행(final-2026-10-27-v2) g01 의 legacy 초과 상품도 같은 꼴('한도대출(마이너스통장)')이었다.

반복 진단(같은 요청을 3회씩, 상품 목록 또는 관측 호출만, 정답 수는 사람이 원문으로 정한 값 — 평가 전용):

## 4. 수정 제안(첫 분석 때 제안. 적용·실험 결과는 §6, 결정할 것은 §7)

1. 상품 분류를 묶음 크기로 나눈다.
   - 한 요청에 들어가는 묶음(`classify.SINGLE_UNIT_LIMITS`: 4쪽·80영역·16,000자·이미지 6장 이하. test-tmp 5개, 개발 18묶음 중 15개):
     legacy 묶음 전체 관측(상품 목록과 영역 배정을 한 호출에서). 이름 없는 대상이 같은 종류(템플릿)의 이름 있는 대상과 같은 광고에 있으면 같은
     상품으로 본다(참고 구현의 "이름이나 종류가 다를 때만 새 상품"). 퇴직연금 상품은 퇴직연금 확인 호출을 그대로 쓴다.
   - 큰 묶음(g06·t07·tmp 같은 여러 파일·여러 쪽): 상품 목록 먼저(inventory-first). [이미지] 줄 버그를 고치고, 끊긴 참조가 있으면 그 페이지를
     조용히 단일 상품에 배정하지 않고 검토 표시한다.
   - `comparison` 정의에서 '다른 상품과의 비교'를 뺀다(두 방식 공통 정책 파일).
2. 빈자리 영역(§2)으로 레이아웃이 놓친 글자를 영역으로 만든다(docs/00 계약 변경).
3. 재판독 선택에 정밀도 조건을 더한다(§5.2).

검증: 1은 기존 파싱 snapshot 으로 의미 단계만 다시 실행한다(test-tmp 5 + 개발 18묶음, 작은 묶음은 같은 요청 3회 반복). 2·3은 영향 받는 페이지만
다시 판독한다.

## 5. 추가 발견

### 5.1 상품 목록 프롬프트의 [이미지] 줄(작성자 버그)

`product_inventory.py::inventory_request` 에서 이미지 역할 목록을 담은 `roles` 변수를 언급 역할 정의 문자열로 덮어써, [이미지] 줄이 그 문자열을
한 글자씩 나열했다("1: c; 2: o; 3: m; …", 204항목). inventory/3 부터이며 E8·E9·E10(각 26회)과 test-tmp(5회)의 상품 목록 호출 전부에 있다.
docs/15 §5 의 E8–E10 수치는 이 버그가 있는 상태의 값이다. §3 진단에서 버그를 고쳐도 상품 수 결과는 비슷했다.

### 5.2 tt02 상단 그림 영역의 문구 유입

- `tt02_p01-v0-L000`(그림 영역 [57,40,1654,1270])의 최종 문구에 아래쪽 두 상품 블록 전체가 들어갔고 깨진 글자('הא기')도 섞였다.
- 1차 페이지 판독의 반복 줄 때문에 재판독(조건 B: 영역 crop + 문맥 이미지)이 돌았고, 모델이 문맥 이미지에서 블록을 읽어 넣었다(notes: "누락된 블록
  제목과 상세 항목들을 원본 이미지에서 직접 읽어 보충").
- 선택 규칙 `page_read.py::select_reread` 는 상자 안 OCR 을 덮는 비율만 비교한다(1차 1.0, 재판독 1.0). 상자 밖 문구 유입은 보지 않아 재판독이
  채택됐다. 검토 표시(`text_from_outside_box`, OCR 근거 글자 비율 0.346)는 붙었지만 의미 단계는 이 문구를 그대로 썼다.
- 제안: 재판독의 OCR 근거 글자 비율이 1차보다 크게 낮으면 1차(반복 줄 정리)를 유지하고 검토 코드를 붙인다. docs/10 에서 고정한 선택 정책을 바꾸는
  일이므로 docs11 회귀 자료로 문구 품질을 다시 확인한다.

## 6. 후속 작업(2026-10-28, Codex 제안 방향)
