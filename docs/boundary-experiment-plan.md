# 긴 이미지 자동 경계 실험 계획(실행 전 고정, 2026-10-25)

대상: f08_p01(667×6130), f09_p01(656×3172), f11_p01(669×2211).

이전 실패는 그대로 유지한다. 경계 VLM 12회 실험(Codex)에서 f08 y=4728(제목-설명 사이)을 반복해서 safe로 오판했고, 버튼 사례(1179/1268)는 선택이 갈렸다.

이 실험 결과로 `validated`를 붙이지 않는다. AI 판정을 `human_review`로 기록하지 않는다. 자동 방식을 승인 목록에 넣는 것은 별도 검증과 합의가 필요하다.

## 1. 정책(실험값, 서버 보장값 아님)

- 최종 타일 비율 한도 `max_tile_aspect = 2.5`.
  - 길이 한도는 폭×2.5이고, 비율 한도 때문에 최소 길이는 폭/2.5다.
  - 값의 출처는 Codex의 탐색 창 실험이며, 검증 대상 정책값이다.
- 탐색(scout) 창: 같은 비율 2.5 창을 50% 겹치게 배치한다. 탐색 결과는 문맥·보호 위치 확인용이며 최종 Region이 아니다.
  - 창 가장자리 2px 이내에 닿은 상자(페이지 끝 제외)는 잘린 관측으로 보고 보호 위치에서 뺀다.
  - 다른 창에서 완전히 관측된 상자만 쓴다.

## 2. 후보 생성(기하, 모델 판단 없음)

- 보호 구간 = 완전 관측된 레이아웃 상자와 글자 있는 OCR 상자의 세로 범위(위아래 4px 여유).
- 보호 구간에 들지 않는 빈 띠(높이 ≥ 6px)의 중앙을 후보 cut으로 둔다.
- 기하 통과는 필요조건일 뿐이다. 의미 안전의 근거는 아니다.

## 3. 비교할 판정 방법(같은 사례에 한 번씩)

| 방법 | 내용 | 호출 |
|---|---|---|
| M1 간격 규칙(모델 없음) | 후보의 빈 띠 높이 ≥ 2.0 × 페이지 OCR 줄 간격 중앙값이면 safe | 0 |
| M2 VLM 관계 분류 | 후보선 위/아래의 탐색 OCR 원문을 ID와 함께 주고, 둘의 관계를 닫힌 목록에서 고르게 함: `independent_sections`, `heading_and_body`, `same_paragraph_or_sentence`, `inside_table`, `button_and_description`, `list_or_condition_continuation`, `unknown`. **코드가 `independent_sections`만 safe로 받는다.** `safe`라는 boolean은 묻지 않는다 | 사례당 1회 |
| M1∧M2 | 둘 다 safe일 때만 safe(추가 호출 없음) | 0 |

- M2의 입력은 후보선 주변 원본 crop과, 같은 crop에 선만 그린 별도 사본이다.
- M2의 근거 ID 검사: 모델이 고른 위쪽/아래쪽 근거 OCR ID가 실제로 선 위/아래에 있는지 코드가 확인한다. 어긋나면 그 판정은 버린다(`evidence_mismatch` → unsafe 취급).
- 반복 호출·다수결·프롬프트 재시도는 하지 않는다.

## 4. 고정 평가 사례(라벨은 모델 실행 전에 원본을 보고 정함)

필수 범주(라벨 = 정답 안전 여부):

- 정상 섹션 사이 공백 → safe
- 제목과 바로 뒤 설명 사이 → unsafe. 음성 대조군 f08 y≈4728 포함
- 표 내부 → unsafe / 표 바깥(표 위·아래 섹션 경계) → safe
- 버튼과 연결된 설명 사이 → unsafe. 음성 대조군 f08 y≈1179·1268 근처 포함
- 같은 문단·조건 목록 내부 → unsafe
- 허용 길이보다 긴 연속 영역: 사례 라벨이 아니라 경계열 구성 단계에서 `oversized_region`이 나오는지 확인한다. 실제 자료에 없으면 '미관측'으로 기록한다.

f08·f09·f11 각각에서 범주가 있는 위치를 고른다. 총 20~24개 사례, M2 호출은 사례 수와 같다.

## 5. 성공·실패 기준(사전 고정)

- **방법 통과 조건**: 고정 사례에서 false-safe(unsafe 라벨인데 safe로 받아들임) **0건**, safe 라벨 재현율 **≥ 50%**.
- **경계열 조건**: 통과 방법의 safe 후보만으로 `compose_sequence`(길이+비율 동시)가 f08·f09·f11 각각에서 전체를 덮는 경계열을 만들어야 한다. 안 되면 `no_safe_boundary`/`oversized_region`과 구체적인 구간을 보고한다.
- **통과하더라도** 이번 결과는 `candidate` 계획으로만 저장한다. 최종 타일 OCR은 실행하지 않는다.
  - 자동 승인을 하려면 더 넓은 검증 세트(다른 긴 광고들)가 필요하다.
  - 경계별 근거 기록과 실패 시 처리 방침에 대한 합의도 필요하다.
- **실패하면**: 자동 경계 미완료로 보고하고, 어떤 범주에서 틀렸는지 남긴다. 같은 실패를 프롬프트를 바꿔 반복하지 않는다.

## 6. 호출 예산

- 탐색 OCR: f08 7창 + f09 3창 + f11 2창 = 약 12회.
- M2 VLM: 사례 수(≤24)회.
- 최종 타일 OCR: 0회(이번 범위 아님).
