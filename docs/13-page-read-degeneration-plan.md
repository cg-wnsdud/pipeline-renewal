# 13. 1차 페이지 판독 반복 퇴화 대응(실행 전 고정, 2026-10-27)

## 배경(저장 기록, 호출 0)

- `tmp-inputs-2026-10-27-r1`의 1차 page 판독 실패 3건은 모두 12,000토큰 한도에서 잘린 반복 출력이다.
  - t01_p01 띠 b1: `L016`(비교 도해, `- X -` 표시)에서 `×` 반복. 13개 중 8개 영역만 응답.
  - t07_p08: `L002`(유의사항 긴 문단, OCR 1,084자)에서 같은 문단 반복. 35개 중 3개만 응답.
  - t08_p02: `L000`(유의사항 긴 문단, OCR 1,158자)에서 반복. 30개 중 1개만 응답.
- 영역 하나의 text 반복이 페이지 응답 전체를 무너뜨리고, 그 페이지 영역 전부(76건)가 재판독으로 넘어갔다. 퇴화 관련 호출 시간은 판독 VLM 호출 시간의 37%다.
- 이전 실행 전체: page 호출 214회 중 length 실패 6회(2.8%). f02_p01(= t01)은 6회 중 3회 실패했다(입력이 같아도 매번 실패하지는 않음).

## 범위

- 바꾸는 것: 1차 페이지 판독 요청의 스키마(영역 text 최대 길이)·출력 한도, 또는 생성 옵션(반복 억제) 중 하나.
- 바꾸지 않는 것: OCR, 영역·bbox, 띠 정책, 입력 이미지(여백 제거 없음), 재판독 조건, 표 판독.

## 단계

1. **서버 기능 확인**(이미지 없는 짧은 요청): JSON 스키마의 `maxLength`가 `["string","null"]` 문자열에 실제로 강제되는지, `frequency_penalty`를 받는지.
2. **기준 재현**: 실패 사례 3개 요청을 Stage 1 기록으로 다시 만들어(원래 호출과 프롬프트·이미지 해시 일치 확인) 각 3회. 출력 한도만 6,000(정상 예상 출력 최대 약 3,700토큰)으로 낮춘다.
3. **개선안**(한 번에 한 요인, 실패 사례 3 × 3회 + 대조 4 × 1회):
   - **I1**: 영역 text 최대 길이. 영역별 상한 `cap = max(300, 3 × 영역 OCR 근거 글자 + 200)`, 스키마 `maxLength`는 페이지 안 상한의 최댓값 하나. 영역 text가 자기 상한을 넘으면 `page_field_truncated`(그 영역만 재판독 대상). 출력 한도 `3 × 판독 단위 OCR 글자 + 1000`(최대 12,000).
   - **I2**: `frequency_penalty` 0.3(1단계에서 받아들여질 때만). 스키마·출력 한도는 기준과 같다.
4. **적용 확인**: 채택안을 코드에 넣은 뒤 tmp 9개 파일 재실행(Stage 1 재사용). 이 단계는 1~3 결과를 보고 따로 결정한다.

대조 4개: t01_p01 띠 b0(정답 f02, 실제 반복 `300만원 이익`·`210만원`), t02_p01(정답 f03), t07_p07(문구 최다 2,746자), t05_p01 타일 t4(긴 유의사항 정상 처리). 대조의 기준값은 r1에 저장된 1차 응답이다(호출 0).

## 측정

- 실패 사례: 페이지 응답 실패(잘림·JSON·계약), 계약을 통과한 영역 수, 상한을 넘은 영역, 호출 시간·출력 토큰.
- 대조: 정답 대조(정확 줄·누락·근거 없는 글자, t01 b0·t02), 기준 출력과의 문구 차이, 실제 반복 문구 횟수, 재판독 조건에 걸리는 영역 수.

## 채택 기준(사전 고정)

1. 실패 사례 9회 모두 페이지 응답이 실패하지 않는다(계약 통과, 잘림 없음).
2. 실패 사례에서 반복에 빠진 영역 외 영역은 계약을 통과한다.
3. 대조: 정답 대조 정확 줄이 기준보다 줄지 않고, 실제 반복 문구 횟수가 보존된다.
4. 페이지 호출 시간 중앙값이 기준보다 늘지 않는다.

I1·I2 중 통과한 안을 고르고, 둘 다 통과하면 문구 변화(부작용)가 적은 쪽을 고른다. 둘 다 미달이면 원인과 자료만 보고하고 기본값을 유지한다.
