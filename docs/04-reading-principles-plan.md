# 판독 원칙 v2 비교 계획(실행 전 고정, 2026-10-25)

## 목적

원본 이미지의 시각적 배치와 문구 관계를 기준으로 VLM이 읽기 순서를 정하게 한다. OCR 결과는 글자 후보와 누락 점검을 위한 참고로만 쓴다. 이 방식이 기존 방식(OCR 초안 제공)보다 나은지 확인한다.

## 비교 조건

| 항목 | 기준선 | v2 |
|---|---|---|
| 일반 영역 지시 | crop/1 | crop/2 |
| 표 후보 지시 | table-check/3 | table-check/4 |
| OCR 참고 표현 | `ocr_draft`(배정 OCR을 원래 OCR 순서대로 나열) + `boundary_ocr`(경계 OCR, inside_ratio·reason 포함) | `ocr_candidates`(배정 OCR과 경계 OCR을 문자열 순으로 정렬, 출처는 in_region/boundary만 표시). 지시문에 "목록 순서는 읽기 순서가 아니다"라고 명시 |
| 판독 원칙 | 위→아래·왼→오른쪽, 요약·교정 금지 | 이미지 기준 읽기 순서(블록·항목-값·도해 묶음), OCR 오독 교정과 원본 표기 보존의 구분, 상품 지식으로 값 변경 금지, 로고·머리글 포함, 연결이 불명확하면 uncertain |
| **고정** | Stage 1 = `work/runs/stage1-merge-large`(200영역, OCR 재호출 없음). 이미지 = 여백 없는 영역 전체 crop. 묶음 = 일반 영역 최대 8장. 표 = 1장씩. 모델·서버·temperature 0 동일. 출력 스키마 동일(일반: region_id/text/uncertain, 표: region_id/is_table/rows string[][]/text/uncertain). 실패 처리 동일(묶음 실패 시 단독 1회) | 같음 |

- 기준선은 같은 지시로 4회 실행한 결과다: full-c1, full-c2, full-c4, full-c2-mixed(동시성만 다름).
- 실행 간 변동 폭은 이 4회의 범위로 잡는다.
- v2는 같은 조건으로 2회 실행한다(동시성 2, cache-bust 없음).
- 판독 지시와 OCR 참고 표현을 함께 바꾼다. 둘을 나눠 보는 요인 분리는 v2 효과가 확인된 뒤 필요할 때만 한다.

## 평가 기준

평가 도구는 `scripts/eval_structure.py`(구조 정답 `fixtures/structure-gold.json`)와 eval/2.1이다. 모두 정답 자료 대조이며, OCR=VLM 일치를 정답으로 보지 않는다.

1. **문구 보존(페이지 단위)**: 분모는 정답 1103줄이다. 소속 영역 정확/근사, 소속 영역 밖·누락을 센다. 영역 단위로는 기대 줄 누락, 근거 없는 글자, 추가 구간(4자 이상)을 센다.
2. **구조 보존**: 연결 단위 보존(32단위)을 '줄은 있으나 순서·블록 혼합'과 '줄 누락'으로 나눠 센다. 표 행 대응(23행)은 text 보존과 따로 센다.
3. **OCR 대비**: 정답 줄마다 같은 위치 OCR의 정오와 VLM의 정오를 비교한다. 다음을 글자·숫자 수준과 기호 포함 수준으로 따로 센다.
   - OCR 오답 추종
   - OCR 정답 손상
   - VLM 교정
4. **검토 표시**: 영역별 '평가상 오류 유무 × 품질 근거 표시 유무'를 센다.
   - 오류인데 표시 없음 = 누락
   - 오류 없는데 표시 = 불필요 가능
5. **계약**: JSON 계약 통과, 판독 실패 수.

**채택 조건**: v2 2회 모두에서 다음을 만족해야 한다.

- 문구 보존이 기준선 범위의 최솟값보다 나빠지지 않는다. 허용 오차는 다음과 같다.
  - 소속 영역 정확+근사: 915줄 이상(기준선 921~925에서 실행 변동 허용 −6).
  - 기대 줄 누락: 27 이하(기준선 20~24, +3).
- 판독 실패는 2 이하다.
- 정상 대조 5건이 모두 통과한다.
- 안정 정상 영역에서 새 오류가 3개 이하이고, 각 오류를 원본으로 확인해 설명할 수 있다.
- 다음 중 하나 이상이 기준선 최댓값보다 개선된다.
  - 연결 단위 보존(기준선 최대 24)
  - 실패 사례 통과 수(기준선 최대 3/14)

기준을 만족하지 못하면 원인 사례를 정리한다. 지시 변경을 무제한으로 반복하지 않고, 필요하면 요인 분리(지시만 변경 / OCR 표현만 변경) 1회를 계획해 따로 기록한다.

## 호출 범위

- 1회 실행 = VLM 50회(일반 묶음 30, 표 20)에 묶음 실패 시 단독 재시도분이 더해진다. OCR 호출은 없다(Stage 1 재사용).
- v2 2회 = 약 100회.
- 기준선 소요는 동시성 2에서 294~598초였다.
- 파일 ID별 예외나 사례별 재시도 분기는 두지 않는다.

### 검토 규칙 수정(모든 실행에 같이 적용)

v2에서 오류 없는 영역의 `ocr_vlm_mismatch`가 7~9건에서 15~16건으로 늘었다. 대부분 OCR 줄은 모두 VLM 출력에 있는데(1.0), VLM이 떨어진 항목과 값을 한 줄로 짝지어 'VLM 글자의 OCR 근거'만 낮아진 경우다.

그래서 VLM 쪽 비교를 줄 단위에서 어절 단위로 바꿨다. 값이 바뀌면 여전히 경고한다(테스트). 기준선 4회와 v2 2회도 같은 규칙으로 재빌드해 비교한다.
