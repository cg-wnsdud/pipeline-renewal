## 2. 자동 경계 정책 `section-pack/2`(새 예시용)

1. **탐색 OCR**: 폭×2.5 창, 50% 겹침. 창 가장자리 상자는 잘린 관측으로 빼고 여러 창 관측을 합친다. 탐색 결과는 최종 결과로 쓰지 않는다.
2. **기하 후보**: 관측된 OCR·레이아웃 상자를 하나도 가로지르지 않는 빈 띠(높이 ≥ 6px)의 중앙.
3. **구성**: 동적 계획법(`compose_sections`). 타일 높이 목표는 폭×2.5이고, 안쪽에 후보가 없을 때만 더 길게 둔다. 타일 수는 최소로 한다.
4. **관계 판정**: 고른 경계마다 VLM 관계 판정(relation/2)을 1회 한다.
   - 허용 관계: `independent_sections`, `table_and_footnote`, `menu_or_tab_and_content`, `button_and_description`, `list_items`.
   - 그 밖의 관계: `heading_and_body`, `same_paragraph_or_sentence`, `inside_table`, `unknown`. 판정 근거 ID가 어긋나는 경우도 포함한다.
   - 그 밖의 관계가 나오면 그 위치를 후보에서 빼고 다시 구성한다. 최대 10회 반복한다.
5. **결과 상태**:
   - 정책이 승인됐고 페이지가 검증 범위 안이며 모든 경계가 허용 관계면 validated다(`semantic_check.method` = `approved_auto_policy`). 승인 기록은 `config/boundary-policy.json`이다.
   - 그렇지 않으면 candidate다.
   - 계획 문서와 근거는 실행 폴더에 저장한다.
6. **정책 검증**(이번에 할 것): f08·f09·f11에 승인 계획 없이 자동 정책을 돌린다. 승인 계획(1)과 비교해 다음을 모두 만족하면 정책을 '검증됨'으로 기록하고 검증 범위를 계약에 적는다.
   - 타일이 원본을 빈틈·중복 없이 덮는다.
   - 정답 줄·표가 경계를 가로지르지 않는다.
   - 레이아웃 상자 안 정답 줄이 승인 계획보다 2줄 넘게 적지 않다.
   - 경계 판정이 금지 관계를 받아들이지 않는다.

   검증 범위는 '모바일 웹 캡처형 세로 긴 이미지(폭 640~700px, 비율 ≥ 3.0)'다. 범위 밖 입력은 candidate로 실행하고 표시한다. 미달하면 원인을 보고하고 새 예시는 candidate로 실행한다.

## 3. 페이지 우선 판독 수정

### (가) 영역 확인은 덮어쓰기가 아니라 보완(region-patch/1)

영역 crop + 1차 페이지 판독 문구를 보내고, 아래 네 가지만 돌려받는다. 문구 전체를 다시 쓰게 하지 않는다.

- `missing`: crop에 보이는데 1차 판독에 없는 문구. 바로 앞 문구(`after`, 1차 판독에 있는 문자열)를 함께 받는다.
- `corrections`: 1차 판독에서 잘못 읽은 글자(`wrong` → `right`). `wrong`은 1차 판독에 그대로 있는 문자열이어야 한다.
- `remove`: crop에 보이지 않는 문구(상자 밖 문구)나, 같은 위치를 두 번 쓴 문구. 1차 판독에 그대로 있는 문자열이어야 한다.
- `uncertain`.

반영은 코드가 한다.

- `wrong`·`remove`·`after`가 1차 판독에 정확히 있을 때만 적용한다(교정·삭제는 첫 1회). `missing`은 `after` 뒤에 새 줄로 넣는다.
- 적용하지 못한 지시는 검토 근거 `patch_not_applied`로 남기고 1차 판독을 유지한다.
- 넣는 문자열은 모두 VLM 응답이다. OCR 문자열을 넣지 않는다.
- 1차 판독이 없는 영역(페이지 출력 실패·ID 누락)은 지금처럼 영역 crop 전체 판독(region-verify/1, 1차 문구 null)을 쓴다.

**확인 조건 추가**: `repeated_text_in_page_read`. 1차 판독에서 같은 줄 조각(정규화 4자 이상)이 영역의 OCR 근거보다 많이 반복되면 확인한다(L022형).

### (나) 크게 줄어드는 페이지는 VLM 입력만 나눔(page-band/1)

- **조건**: 서버 리사이즈 추정 배율 < 0.7인 페이지(현재 f02_p01 0.59, f13_p01 0.42).
- **나누는 방식**: 영역 bbox를 하나도 가로지르지 않는 가로 위치에서만 자른다. 영역 사이 빈 위치 중 가장 넓은 곳을 우선한다. 각 띠의 배율이 0.8 이상이 되도록 띠 수를 최소로 정한다. 그런 위치가 없으면 나누지 않고 사유를 기록한다.
- **판독**: 각 띠를 페이지처럼 page/2로 판독한다(원본 띠 + 표시 사본 + 띠 안 영역).
- **바꾸지 않는 것**: OCR(페이지 전체 1회), 영역 ID·bbox는 그대로다. 띠 사이의 관계 판독은 포기한다.
