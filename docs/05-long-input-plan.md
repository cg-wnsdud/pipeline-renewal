# 긴 이미지 입력 크기 비교 계획(실행 전 고정, 2026-10-25)

## 배경

이전 경계 실험(docs/03 D)은 비율 2.5 창(최대 1640px)을 최종 타일 한도로 전제했다. 이 실험의 결과는 다음과 같다.

- 자동 의미 경계 방법이 기준을 통과하지 못했다.
- f09에서는 우대금리 섹션(y≈0~2131)이 한도보다 길어서 안전한 경계열을 만들 수 없었다(`no_safe_boundary`).

2.5/1640px은 모델 한도가 아니라 실험 정책값이었다. 이번에는 이 값을 한도로 고정하지 않는다. 더 큰 자연 구간과 페이지 전체를 원본 해상도로 넣어 보고, 품질로 허용 입력 범위를 정한다.

## 비교 조건

대상은 f08_p01(667×6130, 비율 9.2), f09_p01(656×3172, 4.8), f11_p01(669×2211, 3.3)이다.

| 입력 | 내용 | 호출 |
|---|---|---|
| S25 | 기존 탐색: 폭×2.5 창, 50% 겹침 | 12회. `work/boundary/exp1`을 재사용하므로 새 호출 없음 |
| W4 | 폭×4 창. 처음과 끝을 맞추고 사이를 균등 배치(겹침 ≥ 1/3) | f08 3, f09 2. f11은 페이지 전체와 같음 |
| WMAX | 4000px 창. 서버 `text_det max_side_limit` 4000 이하라서 텍스트 검출 축소가 없는 최대 길이 | f08 2. f09·f11은 페이지 전체와 같음 |
| WHOLE | 페이지 전체 1장 | f08 1, f09 1, f11 1 |

- 새 OCR 호출은 10회다.
- 레이아웃 옵션(`layoutMergeBboxesMode="large"`)과 기능 옵션은 S25와 같다. 이미지는 원본 PNG를 그대로 보내거나 원본에서 자른 것이다(크기 조정 없음).
- 창 가장자리에 닿은 상자(페이지 끝 제외)는 잘린 관측으로 보고 뺀다. 여러 창의 관측은 합쳐서 페이지 단위로 센다. 이것은 입력 크기별 '관측 품질' 비교이며, 최종 결과(중복 제거·타일 확정)가 아니다.

## 평가(정답 대조, `fixtures/gold`)

정답 줄(선택 항목 제외) 기준으로 다음을 센다.

1. 레이아웃 상자 안: 정답 줄 면적의 50% 이상이 관측된 레이아웃 상자 안에 있는 줄 수.
2. OCR 줄이 상자에 엄격 포함: 같은 위치(IoU ≥ 0.5)의 OCR 줄이 레이아웃 상자에 완전히 들어가는 줄 수. 통합 경로에서 영역에 배정될 수 있는 줄이다.
3. OCR 정답: 같은 위치 OCR 원문이 글자·숫자 수준에서 정답과 같은 줄 수. 기호 포함 수준도 함께 기록한다.
4. 정답 표(f09-benefit)가 표 상자 하나 안에 모두 들어오는지, 그리고 표 상자 수.
5. 텍스트 검출 배율(서버 보고값 기반 추정). 1.0 미만이면 축소된 것이다.

## 판정 규칙

**통과 조건**: 페이지별로 입력 X가 아래 조건을 모두 만족하면 그 페이지에서 '허용'이다.

- 레이아웃 상자 안 줄 수 ≥ S25 − 2
- 엄격 포함 줄 수 ≥ S25 − 2
- OCR 정답(글자·숫자) ≥ S25 − 2
- S25에서 정답 표가 한 상자 안이었다면 X도 그래야 한다

허용 범위는 통과한 입력 중 가장 긴 길이와 비율로 정한다.

통과 결과에 따라 다음과 같이 처리한다.

- **WHOLE이 통과한 페이지**: 경계 없이 페이지 전체를 OCR 1회로 처리할 수 있다. 통합 경로의 라우팅 정책에 허용 범위(최대 비율·최대 길이, 근거 = 이 실험)를 넣고, 해당 페이지를 READY로 처리한다. 자동 경계 확정이 아니므로 `human_review`나 `validated`는 쓰지 않는다.
- **WHOLE이 통과하지 못한 페이지**: 통과한 가장 긴 창 길이를 최종 타일 길이 한도 후보로 기록한다. 경계 검증은 여전히 필요하다. 미검증 경계를 자동 확정하지 않고, 페이지는 보류(사유 표시)로 둔다.
- **창 결과의 쓰임**: 탐색용 겹침 창 결과는 최종 결과로 쓰지 않는다. 겹침이 최종 결과의 중복으로 남지 않게 하기 위해서다.

**결과 해석의 한계**:

- 대상은 3페이지뿐이므로, 허용 범위는 이 자료에서 관측한 범위로만 기록한다(잠정).
- S25도 정답이 아니다. S25보다 나쁘지 않은지를 보는 비교다.

## 결과(2026-10-25, `work/long/exp2/eval.md`)

새 OCR 호출은 10회이며 모두 성공했다. S25는 기존 탐색 12회를 재사용했다.

| 페이지 | 입력 | 호출 | 레이아웃 상자 안 정답 줄 | OCR 줄 엄격 포함 | OCR 정답(글자·숫자) | 정답 표가 한 상자 안 | 텍스트 검출 배율 |
|---|---|---:|---:|---:|---:|---|---|
| f08 (101줄) | S25 | 7 | **99** | 56 | 99 | - | 1.10 |
| | W4 | 3 | 88 | 54 | 98 | - | 1.10 |
| | WMAX | 2 | 59 | 35 | 100 | - | 1.0 |
| | WHOLE | 1 | **2** | 0 | 98 | - | **0.65(축소)** |
| f09 (72줄) | S25 | 3 | **51** | 33 | 62 | 예 | 1.12 |
| | W4 | 2 | 44 | 29 | 61 | 예 | 1.12 |
| | WHOLE(=WMAX) | 1 | 46 | 25 | 60 | 예 | 1.12 |
| f11 (45줄) | S25 | 2 | **39** | 32 | 44 | - | 1.10 |
| | WHOLE(=W4=WMAX) | 1 | 27 | 12 | 43 | - | 1.10 |

**판정**(사전 규칙, S25 대비 −2 이내):

- 세 페이지 모두 W4·WMAX·WHOLE이 '레이아웃 상자 안' 조건을 통과하지 못했다(−5~−97줄). 따라서 **더 큰 입력은 허용하지 않는다.**
- OCR 글자 정확도는 입력 크기와 거의 관계가 없었다. 예외는 f08 WHOLE로, 텍스트 검출이 0.65배로 축소되어 기호 포함 수준에서 정답이 97→94줄로 줄었다.
- 품질 차이는 레이아웃 검출에서 생긴다. 레이아웃 모델 입력이 고정 크기로 줄어들기 때문으로 추정한다(서버 코드 미확인).
- f11 WHOLE의 상자를 원본 위에 그려 보면, 글머리 항목 여러 개가 레이아웃 상자 밖으로 빠진다. 수치 차이가 실제 검출 누락이라는 뜻이다.

**결론**:

- 이 자료에서 허용되는 입력은 폭×2.5 창(S25)뿐이다. 3페이지에서 관측한 잠정값이다.
- 긴 페이지는 폭×2.5 이하 타일과 검증된 경계가 필요하다. 그런데 자동 경계 방법이 기준을 통과하지 못했다(docs/03 D). 그래서 f08·f09·f11은 **보류**한다.
- 보류 사유는 `config/routing.json`의 `long_route.hold_reason`으로 결과와 화면에 표시한다.
- 미검증 경계를 확정하지 않았고, `human_review`를 기록하지 않았다.
- **남은 결정(사용자)**:
  - f09 우대금리 섹션(y≈0~2131)은 폭×2.5(1640px)보다 길고 안쪽에 안전 경계가 없다.
  - 선택지 A: 이 섹션만 레이아웃 품질 저하를 감수하고 더 긴 타일(W4 수준)로 넣는다.
  - 선택지 B: 겹침 타일 두 장으로 나눠 OCR하고, 겹친 부분 결과를 어떻게 하나로 정할지 규칙을 새로 정한다.
  - 선택지 C: 사람이 경계를 지정한다(`human_review`).
  - 어느 쪽이든 정책 결정이 필요하다.
