# 07. 판독 원칙 비교 · 평가 확장 · 화면 · 서버 · 긴 이미지: 종합 보고(2026-10-25)

이 보고는 모델 호출 성공, JSON 계약 통과, 내용 품질 통과를 구분한다. 내용 품질은 정답이 있는 16페이지에 대한 평가이며, 통과로 표시하지 않는다.

## 1. 이미 구현돼 있던 기능(이번에 바꾸지 않음)

- **통합 경로**: 입력 → 페이지 준비(이미지·PDF·HWP/HWPX 변환 연결) → 일반 페이지 OCR 1회 → `layout_det_res.boxes` 원본 bbox·ID 그대로 Region → 엄격 포함 배정 / 미배정 보존(원문·좌표·점수·사유) → 모든 Region VLM 판독 → `result.json`·`trace`·화면.
- **요청 형식**: 일반 영역은 영역 전체 crop 묶음(최대 8장), 표 후보는 table-check 단독 요청. 묶음이 실패하면 단독 요청 1회를 보낸다.
- **긴 이미지**: 검증된 경계 문서가 없으면 OCR하지 않고 보류한다.
- **평가**: eval/2.1 페이지·영역 단위 평가.

## 3. 판독 원칙 비교(docs/04: 사전 계획 → 결과 → 판정)

| 조건 | 일반 / 표 지시 | 실행 | 정확+근사(/945) | 기대 줄 누락 | 연결 단위(/32) | 표 행(/23) | 사례 통과(/19) | 안정 영역 새 오류 |
|---|---|---:|---|---|---|---|---|---|
| 기준선 | crop/1 / table-check/3 | 4 | 921~925 | 20~24 | 21~24 | 11~23 | 5~9 | 0 |
| v2 | crop/2 / table-check/4 | 2 | 912·937 | 33·9 | 31·28 | 16·23 | 13·14 | 3·4 |
| v3 | crop/3 / table-check/5 | 3 | 923·921·913 | 22·24·32 | 28·29·26 | 23·23·16 | 13·14·12 | 2·3·3 |
| v3h | crop/3 / table-check/3 | 1 | 914 | 31 | 28 | 16 | 10 | 2 |
| **최종 실행** | crop/1 / table-check/3 | 1 | **906** | **38** | 24 | 19 | 8 | 2 |

- 표의 v2·v3 수치는 '표 text 빈 값 보완' 규칙을 적용한 재빌드 기준이다. 적용 전 v3a·v3b는 909·907이었다.
- **판정**: 사전 기준(정확+근사 ≥ 915, 누락 ≤ 27 등)을 v3c와 v3h가 근소하게 넘지 못했다. 그래서 **기본값은 crop/1·table-check/3을 유지**하고 채택은 사용자 판단으로 넘긴다.
- **기준선 변동**: 최종 실행은 기준선과 같은 지시로 돌렸는데도 906/38로 기준선 4회 범위를 벗어났다. 원인은 f07_p02 L000 5열 중 1열만 출력, f12_p01 L000 로고 생략, f01 L006 표 퇴화다. 세 영역 모두 품질 근거로 표시됐다. 기준선 실제 변동은 4회 측정보다 넓고, v3c·v3h의 미달 폭(−2, −1)은 이 변동 안에 있다. 다만 사전 기준은 결과를 본 뒤 바꾸지 않았다.

### 개선(v2·v3, 원본 대조로 확인)

- **읽기 순서·블록**: 연결 단위가 26~31/32로 늘었다(기준선 21~24).
  - 항목-값 2줄 섞임(f13 L010)과 라벨 행·값 행 5열(f05 L001)을 짝지어 썼다.
  - 도해(f02 L016)를 'A 운용사 펀드 -X- B 운용사 펀드 / 변경불가'처럼 구조대로 썼다. 기준선은 OCR 순서를 그대로 나열했다.
- **로고·머리글 생략**: f01 L004, f02 L022, f06 L005가 기준선 4/4회 생략에서 v2·v3 7/7회 전사로 바뀌었다.
- **표 판독 실패 f01 L006**: v3 3/3회 통과했다(기준선 1/4).
- **OCR 정상 교정 대조 f02 L020**: '금용'→'금융' 교정을 모든 조건에서 유지했다.

### 악화·미해결

- **f02 L004 왼쪽 설명 문단 생략**: crop/3 4/4회, crop/2 1/2회. 기준선은 4/4회 포함했다. **v3 일반 지시의 체계적 결함**이다.
- **f12_p02 L017·L021**: crop/3에서 기본금리 값 줄을 맨 앞으로 옮겨 항목-값 단위가 깨졌다(4/4회).
- **f02 L002 표 반복 출력**: 출력 한도 6000토큰에서 잘린다. 기준선 4회 중 0회, 이후 7회 중 3회였다(table-check/3 포함). 지시와 관계없는 실행 간 변동이다.
- **'OOOD'**: 그림을 읽은 OCR 후보를 문구로 옮겼다(v3 3회 중 1회).
- **지시로 바뀌지 않은 것**: 원본 표기 변경('법를'→'법을', '으로서'→'로서', '관련한'→'관련된')과 배지 '5천만원'(원본 '1억원')은 모든 조건·모든 실행에서 남았다. 모두 품질 근거로 표시된다.
- **OCR 오답 추종(글자·숫자 수준)**: 모든 조건에서 1~2줄이다(적세효과 등).
- **OCR 정답 손상**: 기준선 22~27줄이다. 대부분 생략과 판독 실패이고, 원본 표기를 '교정'한 경우도 포함된다.

## 4. 보존·계약 결과(최종 실행 `work/pipeline/final-2026-10-25`)

**모델 호출**: OCR 16회, VLM 50회 모두 응답을 받았다. VLM 응답 중 1건(f01 L006 표)은 출력 퇴화로 JSON 계약에 실패했다. 이 영역은 `read_failed`로 남기고 OCR 참고(`final=false`)를 붙였다.

**JSON 계약 검사 통과**:

- 원본 bbox와 Region ID는 Stage 1과 같다. 새로 실행한 Stage 1은 기준 Stage 1(`stage1-merge-large`)과 19페이지 모두 영역·OCR이 같았다.
- Region 200개를 모두 보존했다(read 197, no_text 2, read_failed 1).
- 미배정 OCR 수가 Stage 1과 같다.
- 표 아님 판정(2건)도 영역과 문구를 보존했다.

**내용 품질(평가, 통과로 표시하지 않음)**: 정답 1103줄 기준이다.

- 소속 영역 정확 868 / 근사 38.
- 미배정 OCR 원문에만 141(웹 레이아웃 미검출).
- 판독 실패 영역 OCR에만 9, 누락 22.

**검토 표시**:

- 평가상 오류가 있는 영역 26개 중 14개에 품질 근거가 표시됐다.
- 오류가 없는 영역 174개 중 10개에도 품질 근거가 붙었다.
- 맥락 근거는 경계 걸침 146, 겹침 4, 겹친 영역 중복 문구 2, 표 아님 2다.

## 5. 긴 이미지(docs/05)

**입력 크기 비교**: 탐색 창(폭×2.5) 대비 정답 대조로 비교했다. 새 OCR은 10회다.

- 폭×4, 4000px, 페이지 전체 입력은 세 페이지 모두 '레이아웃 상자 안 정답 줄'이 5~97줄 적었다.
- f08 페이지 전체는 상자가 2개뿐이었고, 텍스트 검출도 0.65배로 축소됐다.
- 그림으로도 실제 누락을 확인했다(f11 글머리 항목 누락).
- 그래서 **더 큰 입력은 허용하지 않는다.**

**현재 상태**: f08 `BOUNDARY_CANDIDATE_UNVALIDATED`, f09·f11 `BOUNDARY_PENDING`.

- 보류 사유를 결과와 화면에 표시한다.
- 미검증 경계를 확정하지 않았고, `human_review`를 기록하지 않았다.
- 탐색 창 결과는 최종 결과에 쓰지 않는다.

## 6. 서버 대기 항목(docs/06)

- **클래스별 dict 패치**: **미적용**(읽기 전용 확인 8회).
  - `{"2":0.4}` 결과가 숫자 0.5와 같은 10상자였다(기본 13).
  - 잘못된 키·값도 200으로 수락됐다.
- **영향**: 현재 경로는 threshold를 보내지 않고 병합 모드는 문자열 `"large"`라서 영향이 없다.
- **할 일**: 패치 계약과 1~3차 검증 항목을 문서로 정리했다. 클래스별 threshold 실험(웹 레이아웃 누락 감소)은 패치 검증 후에 한다.
- **추가 확인 필요**: 병합 dict는 h01_p03으로 판별할 수 없다. 기본과 union이 다른 이미지로 확인해야 한다.

## 7. 사용자 판단 사항

1. **판독 지시 채택**: crop/3을 쓸지 정해야 한다.
   - 장점: 읽기 순서·로고·도해 개선.
   - 결함: f02 L004 설명 생략·L017/L021 순서 변경(체계적).
   - 선택지: 기준선 유지, crop/3 채택, L004형 결함을 겨냥한 지시 수정 실험 1회.
2. **표 출력 퇴화 대응**: 같은 요청 1회 재실행(일반 규칙) 또는 출력 한도 조정. 둘 다 정책 결정과 별도 비교가 필요하다.
3. **큰 영역 일부 생략**: f07_p02 L000, f12_p01 L000 같은 영역이 실행마다 일부 생략된다. 품질 근거가 붙은 영역을 1회 재판독하는 규칙을 둘지 정해야 한다.
4. **지시로 고쳐지지 않는 오류**: 원본 표기 변경과 배지 금액은 사람 검토 범위로 둘지 정해야 한다(품질 근거로 표시됨).
5. **f09 긴 섹션**: y≈0~2131로 폭×2.5보다 길고 안쪽에 안전 경계가 없다. 처리 방침(더 긴 타일 / 겹침 타일과 병합 규칙 / 사람 경계 지정)을 정해야 한다.
