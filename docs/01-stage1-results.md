# 01. Stage 1 결과 — 입력 · 레이아웃 영역 · OCR 배정

기준일: 2026-10-24.

**실행 조건**
- 이미지·PDF 15페이지와 HWP 4페이지(`fixtures/manifest.json` + `manifest-hwp.json`).
- 요청 기능 옵션: 보정·표 구조·수식·도장 OFF. 검출 문턱값은 보내지 않음(서버 기본).
- PDF 200DPI(정답 좌표계와 같게 맞추기 위한 비교 조건이며 확정값이 아님).
- OCR 동시 1.

**이번 단계에서 하지 않은 것**: VLM 호출, 긴 이미지 경계 확정. 최종 문구 정확도는 측정하지 않았다.

## 1. 입력과 호출

- 19페이지 모두 새로 렌더했다. 정답 좌표계(기존 200DPI 렌더)와 PNG sha256이 일치한다. HWP는 이번 실행에서 `hwp_bridge`로 새로 변환했고(13.6초, ASCII 정션 사용) 결과 해시도 같다.
- **A4·정사각형 10페이지는 모두 전체 이미지 OCR 1회였다**(호출 기록 기준).
  - 해당 페이지: f01, f04, f07 p1·p2, f12 p1·p2, h01 p1~p4.
  - 각 호출에서 확인한 것: 입력 범위 = `[0,0,W,H]`, 보낸 바이트의 sha256 = 페이지 PNG, 응답 width/height 일치. 근거는 `calls.json`과 `report.md` 1절.
- 일반 비율 페이지도 전체 1회였다: f02 2.27, f03 1.17, f05 1.74, f06 2.08, f10 2.27, f13 1.78.
  - f13(2881×5120)은 서버 `max_side_limit=4000` 때문에 텍스트 검출 입력이 약 0.78배로 축소되는 것으로 추정된다. f02(4081px)도 0.98배다. `TEXT_DET_DOWNSCALED` 정보로만 기록하고 분할하지 않았다.
- 긴 이미지 f08(9.19)·f09(4.84)·f11(3.30)은 `BOUNDARY_PENDING`이다. 확정 경계 문서가 없어 OCR·영역을 만들지 않았다. 균등 분할도 하지 않았다.

## 2. 영역 검출 성공(정답 줄 기준) — 미통과

> **정정(후속, docs/02 1절)**: 아래 78.6%는 배정 규칙(core 0.25)을 정답 줄에 적용한 단일 배정률이다. 검출 재현율이 아니다.
> 지표는 고정 기하 기준(`exact-containment/1`)의 미포함/일부/단일/복수와 배정 정책 단일 배정률로 분리했다.
> 기본 배정 규칙은 감사 후 엄격 포함으로 바꿨다. 현재 수치는 docs/02 를 본다.

정답 줄(선택 항목 제외)이 레이아웃 영역 **하나**에 배정 기준으로 들어가는지 본 지표다. 문구 정확도와는 별개다.

- **기본 조건: 867/1103(78.6%)**. 처리한 16페이지 기준이며 긴 이미지 3장은 빠져 있다.
- 실패는 두 종류다.
  1. **레이아웃 누락(영역 밖)**: 웹 캡처에 몰려 있다. f05 45/71, f04 31/100, f06 26/88, f02 25/204, f03 22/74, h01_p01 7/31. 메뉴·탭·버튼·날짜 선택·푸터가 영역 없이 남는다(`#f05_p01`).
  2. **원시 영역의 중첩(모호)**: 문서형 페이지에 많다. f01 20, f13 19, f12_p02 15, f10 5, f12_p01 5.
     - 예 1: f01에서는 큰 `text` 영역 L038이 L023·L025·L027·L029·L037을 포함하고, L036이 L039·L042를 포함한다(`#f01_p01/f01_p01-v0-L038`).
     - 예 2: 같은 페이지의 L007은 L033·L035와 99.9% 겹친다(`#f01_p01/f01_p01-v0-T034`).
     - 이런 글자는 어느 영역 소속인지 정하지 않고 미배정으로 남겼다.
- 부분 포함은 2건이다. f07_p02 T042 "농협은행/202…"는 포함비 0.47, 53px 돌출. h01_p02 T002 "있다."는 0.75, 16px 돌출.
- 서버 `parsing_res_list`는 199블록이고 원시 `layout_det_res`는 239상자다. 대응 블록이 없는 원시 영역은 39개다. Region에는 원시 상자만 썼다. 서버 블록은 화면의 회색 점선 비교 레이어로만 표시한다.

### 검출 설정 비교(R1 일부): `layoutThreshold=0.3`은 채택하지 않음

| 지표 | 기본 | 0.3 |
|---|---:|---:|
| 영역 / 표 후보 | 239 / 20 | 351 / 31 |
| 미배정: 영역 밖(글자 있음) | 188 | 14 |
| 미배정: 모호(원시 중첩) | 79 | 272 |
| 정답 줄 단일 영역 포함 | 867 (78.6%) | 827 (75.0%) |

- 0.3은 웹 캡처의 누락을 거의 없앤다. f05 26→58, f04 69→83, f06 62→82.
- 대신 문서형 페이지에서 큰 컨테이너 상자가 늘어 중첩이 커진다.
  - h01_p03: 점수 0.354의 `table` 상자가 페이지 거의 전체([123,149,1524,2159])를 덮어 정답 줄 34→0.
  - f12_p02 87→61, f01 65→54, f07_p01 69→55.
- 두 조건 모두 통과가 아니다. 남은 문제는 "누락 vs 원시 중첩"의 맞교환이고, 문턱값 하나로는 풀리지 않았다. 클라이언트 합집합·병합으로 숨기지 않았다.

## 3. OCR 표 후보

- 기본 조건에서 `label=="table"` 원시 영역은 20개다. VLM 계획에서는 이 20개만 `table_check`이고, 나머지 219개는 `read_text`다(계획만 했고 실행하지 않음).
- 정답 관계 파일에 기록된 표만 기준으로 보면 다음과 같다. 이 목록은 모든 표를 망라하지 않는다.
  - f13 우대금리표 2개: 각각 후보 하나에 100% 들어감.
  - f13 좌우 상품 정보(항목-값 목록) 2개와 f12_p02 정보 2개: **표 후보 아님**(누락). 일반 영역으로는 판독 대상이지만 표 검출 통과로 표시하지 않는다.
- 거짓 표 의심: f07 p1 L007, f07 p2 L005(상단 메뉴, 점수 0.55). 후속 `table_check`로 판정할 대상이다. 거짓이어도 같은 bbox·문구로 남는다.

## 4. OCR 글자 보존

- **분할 검증**: 원시 OCR 1159항목(빈 문자열 13개 포함)이 배정 + 미배정 1159와 정확히 일치한다. 누락·중복·없는 영역 참조는 0이다. 원시 레이아웃 상자 239 = Region 239.
- **글자 있는 OCR 1146개의 분류**
  - 배정 877개: 정확 포함 702 + 허용 오차 175.
  - 미배정 269개: 영역 밖 188, 모호 79, 부분 2.
  - 미배정 항목은 모두 `ocr_id, page_id, view_id, ocr_text, ocr_bbox, score, reason, candidates`를 갖는다. 출처는 `overall_ocr_res`, `review_required=true`, `final=false`이며 Region으로 승격하지 않았다.
- **허용 오차로 배정된 항목**: 돌출이 가장 큰 세 건을 원본에서 확인했다. f01 T011 19.9px, h01_p01 T014 18.8px, f13 T008 15.4px. 모두 글자 잉크는 영역 안이고 OCR 상자 여백만 밖이다. 대조 화면에서는 초록 점선으로 따로 보인다.
- 빈 문자열 OCR(예: f01 T032, 녹색 세로 막대)도 보존했다. 화면에서는 회색 점선으로 구분한다.

이 결과는 "OCR이 읽은 항목이 하나도 사라지지 않았다"는 뜻이다. OCR 글자가 맞다는 뜻은 아니다. 레이아웃과 OCR이 함께 놓친 글자는 이 검증으로 찾을 수 없다.

## 5. 최종 문구 정확도

미측정이다. VLM 판독을 실행하지 않았다. `stage1.json`의 Region `text`는 `null`이고, 화면의 "OCR 초안"은 최종 문구가 아니다.

## 6. 남은 일과 결정이 필요한 지점

1. **원시 중첩 처리 방침**: 지금은 지시대로 모호 글자를 미배정으로 둔다. 중첩을 그대로 두면 영역 하나에 들어가는 비율이 낮게 유지된다. 다음 비교 후보는 서버 요청 옵션 쪽이다(문턱값을 class별로 따로 주는 것, 서버의 상자 중첩 처리 옵션). 클라이언트 병합은 후보가 아니다.
2. **웹 캡처 레이아웃 누락**: 기본 조건의 웹 화면 누락은 검출 설정 문제로 기록했다. 자동 타일링으로 숨기지 않았다.
3. **긴 이미지**: `boundary-plan/1`(docs/00 2절)이 `validated`로 들어오면 타일 OCR·offset·타일 경계 영역 표시가 바로 동작한다(오프라인 테스트로 확인).
4. **아직 하지 않은 것**: PDF 300DPI 비교, R3 일반 영역 판독 입력 비교, R4 표 후보 확인, HWPX 실제 샘플.
